## 1. V3.0 的定义

V3.0 = **可用的「故事创作 + 镜头设计 + 审核」闭环**，交付 P0~P8。

**V3.0 不要求一次性完成全部视频生成与后期功能。** 短剧生产的完整链路（图片/视频/配音/音效/合成/导出）作为 P9 接入，架构必须预留接口，但不作为 V3.0 的阻塞交付。

判定标准：用户能从一个空白项目出发，生成多角色完整故事，逐阶段人工审核，拆出场景与镜头，单独修改并重新生成某个镜头，并完成安全迁移旧项目。

## 3. V3.0 暂缓的功能（架构预留，不在 V3.0 交付）

| # | 功能 | 暂缓原因 | 预留方式 |
| --- | --- | --- | --- |
| 1 | 视频生成完整链路 | 依赖第三方视频服务，成本与稳定性未验证 | `video` 槽位 + `<VideoProvider>` 接口预留 |
| 2 | 音频制作完整链路（音效/BGM 智能编排） | V2 已有配音能力（`voice`），但「智能编排」需要实测 | `audio` 槽位预留（与 `voice` 分开配置）；`voice` 槽位沿用 V2 已实现的配音能力 |
| 3 | 后期合成与导出自动化 | 依赖 V3 镜头实体稳定后再做 | WorkflowEngine 中 `post_prod` / `export` 阶段 ID 已固定 |
| 4 | MysteryPack（第二种题材包） | 拖慢核心交付；接口抽象质量由 HorrorPack + 代码评审保证 | GenrePack 接口已定义 |
| 5 | 全球网络故事搜索与改编 | 独立模块，不属于 V3.0 核心 | 作为独立后续项目 |
| 6 | 商业化能力（多租户/计费） | 产品定位为个人创作者工具 | 不做 |
| 7 | GUI 全量自动化测试 | 渐进补充 | 每阶段增加冒烟用例 |
| 8 | SQLite / 数据库存储 | 接口已预留 | Repository 接口可映射 |
| 9 | 项目级共享资源的跨 Story 自动重新审核编排 | 基础共享能力已在 V3.0 交付（§2 第 21 项）；自动编排依赖 P6 稳定与大量真实使用 | `DependencyImpact` 记录 + `referrers()` 接口已预留（见[目标架构 §6.3.2](V3_STAGE0_TARGET_ARCHITECTURE.md#632-共享资源审核记录归属p2--p6-实现约束)），后续只增加编排逻辑 |

> 暂缓 ≠ 放弃。每项都在架构中留有接口边界，P9 及后续版本接入时不需要改动核心数据模型。

## 4. V3.0 完成判定（验收清单）

V3.0 视为完成需同时满足：

1. §2 的 21 项能力全部通过验收（原 20 项 + Stage 0.6 新增的共享资源基础能力）；
2. 309 个 V2 原有用例全部保留且通过（或经审查确认的等价替换）；
3. 迁移 23 类场景通过，失败场景证明原项目未被破坏；
4. 一个真实 V2 项目完成端到端迁移并人工核对；
5. 一个完整故事从创意到镜头设计走完全部人工门禁；
6. [开发路线 §3.4](V3_STAGE0_5_DEVELOPMENT_ROADMAP.md#34-真实端到端验收stage-06-新增) 中属于 V3.0 阶段的端到端验收（E3 / E5 / E6 / E7 / E8 / E9 / E10，以及 Mock 方式执行的 E1 / E2 / E4；E3 为模型对比，需真实 API 与费用授权）完成并留下记录；
7. 所有 `OPEN QUESTION` 中「阻塞开发」的项已有明确答复并落到配置或文档；非阻塞项可以继续保持 OPEN（见[冻结基线 §11](V3_STAGE0_6_FINAL_BASELINE.md#11-open-question-总表)）。
